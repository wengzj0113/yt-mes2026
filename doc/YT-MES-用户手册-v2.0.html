YT-MES 电芯追溯系统 使用手册

版本 v2.0 — 2026 年 5 月

1. 系统简介

1.1 系统概述

YT-MES（Yuntong Manufacturing Execution System）是一套面向锂电池电芯生产的全流程追溯系统。 系统覆盖从原材料配料到成品分选的 13 道核心工序，提供批次管理、工序维护、工序录入、 质量检验、原材料仓储、大屏数据看板以及基于条码的电芯级全生命周期追溯功能， 帮助企业实现生产过程数字化与质量可追溯。

v2.0 版本新增了工序主数据管理、现场扫码聚合操作台、工业级大屏看板 以及分选机硬件数据接口，进一步提升了车间操作效率和数据可视化能力。

1.2 核心目标

  • 全流程追溯 — 以批次（Batch）为主线串联 13 道工序，最终实现单个电芯从原料到成品的完整追溯
  • 质量控制 — 每道工序均支持操作工记录与质检审核，不合格品可跟踪处置
  • 高效录入 — 扫码聚合操作台大幅提升车间数据录入效率，减少页面跳转 v2.0
  • 物料管理 — 原材料入库、领用、批次关联，确保物料流向可查
  • 数据可视化 — 工业级大屏看板实时展示生产数据链路，支撑管理决策 v2.0
  • 设备集成 — 支持分选机等硬件设备通过 API 自动上传电芯数据 v2.0

2. 快速上手

2.1 访问系统

打开浏览器（推荐 Chrome / Edge 最新版），在地址栏输入系统访问地址：

http://localhost:3000

2.2 登录

在登录页面输入用户名和密码
点击"登录"按钮
系统验证通过后自动跳转到工作台
提示：系统预置了测试账号（密码均为 admin123），详见 第 11 章 用户与权限。

2.3 界面布局

登录后进入主界面，布局如下：

  • 左侧导航栏 — 包含所有功能模块入口。v2.0 新增了"现场扫码录入"和"大屏看板"菜单项
  • 顶部栏 — 显示系统名称、当前用户及退出登录按钮
  • 主内容区 — 显示当前功能模块的内容

2.4 基本操作流程

创建批次 — 在批次管理页面新建生产批次
录入工序 — 使用"现场扫码录入"扫批次条码，在操作台中逐工序录入数据 推荐
质检审核 — 质检员对各工序记录进行审核判定
导入条码 — 在电芯条码管理页面导入该批次的电芯条码，或通过分选机自动上传
追溯查询 — 通过条码查询单个电芯的全生命周期数据

3. 工作台

3.1 功能概述

工作台（Dashboard）是用户登录后的首页，展示生产关键指标的概览信息，并可作为跳转到大屏看板的入口。

3.2 统计卡片

工作台顶部展示 4 个统计卡片：

指标说明
总批次系统中所有批次的总数
进行中当前状态为"进行中"的批次数量
已完成当前状态为"已完成"的批次数量
已关闭当前状态为"已关闭"的批次数量

3.3 最近批次

统计卡片下方展示最近创建的批次列表，包含批次号、产品型号、状态和创建时间等信息，便于快速访问。

3.4 大屏看板入口 v2.0

通过左侧导航栏的"大屏看板"菜单或直接访问 /big-screen 路由，可打开工业级数据大屏看板。大屏采用 16:9 等比缩放适配，支持在 1080P / 4K 显示屏上完美展示。详见 第 7 章 大屏看板。

4. 批次管理

4.1 功能概述

批次（Batch）是生产管理的核心单元。每一批电芯从创建批次开始，到完成所有 13 道工序并关闭批次结束。批次号是串联所有工序记录和电芯条码的唯一标识。

4.2 批次列表

通过左侧导航"批次管理"进入批次列表页面。

  • 搜索 — 按批次号、产品型号、产品规格等关键字搜索
  • 筛选 — 按批次状态筛选
  • 分页 — 系统支持分页浏览，每页显示多条记录

4.3 创建批次

在批次列表页面点击"新建批次"按钮
在弹出的对话框中填写以下信息：
  • 产品型号 — 如 YT-4680
  • 产品规格 — 如 4680-20Ah
  • 生产车间 — 如 A1 车间
  • 班次 — 白班 / 夜班
  • 计划数量 — 计划生产电芯数量
  • 备注（可选）
点击"确定"提交，系统自动生成批次号
批次号规则：{工厂代码}{年份后两位}{月份字母}{4位随机字符}，例如 WT26A1XZ8。工厂代码在系统配置中设置。

4.4 批次详情

点击批次列表中的批次号进入批次详情页。详情页包含以下内容：

  • 批次信息 — 批次号、产品型号规格、车间班次、创建信息等
  • 工序状态 — 13 道工序的完成状态总览，用不同颜色标识：
    • 未开始
    • 草稿（操作工已保存但未提交）
    • 已完成（已提交并通过）
    • 异常
  • 电芯列表（选项卡）— 该批次已导入的电芯条码列表

4.5 批次状态说明

状态编码说明
草稿1批次已创建，尚未开始生产
进行中2已有工序开始记录
已完成3所有工序已完成
已关闭4批次关闭，不可再修改

5. 工序管理 v2.0 重构

5.1 功能概述

在 v2.0 中，"工序管理"已重构为工序主数据管理模块。它的核心职责是对系统中的工序定义进行 增删改查维护，包括工序的名称、编码、排序号、启用状态等元数据。

区分："工序管理"用于维护工序字典本身（管理员配置），而"现场扫码录入"用于车间操作工录入每天的生产数据。 两者通过字典动态联动：在工序管理中停用一个工序，现场扫码操作台中将同步隐藏该工序的卡片。

5.2 工序定义

每个工序包含以下字段：

字段说明示例
工序编码系统内部的唯一标识（英文）coating
工序名称显示在界面上的中文名称涂布
排序号决定工序在列表和操作台中的显示顺序20
状态启用 / 停用启用
备注说明对该工序的补充描述（可选）—

5.3 权限说明

本页面采用页面可见、按钮受控的 RBAC 权限模式：

  • 所有登录用户：可查看工序列表、使用搜索筛选和分页
  • 仅管理员（admin）：可见右上角"新增工序"按钮和列表右侧"编辑/删除"操作列

5.4 搜索与筛选

页面顶部提供搜索栏，支持以下筛选条件：

  • 关键字 — 按工序编码或工序名称模糊搜索
  • 状态 — 按启用 / 停用筛选

5.5 新增工序

使用管理员账号登录
点击右上角"新增工序"按钮
在弹出对话框中填写工序编码、名称、排序号和状态
点击"确定"保存

5.6 编辑工序

在列表中点击目标工序的"编辑"按钮
在弹出对话框中修改需要变更的字段（工序编码不可修改）
点击"确定"保存

5.7 删除工序与安全防错

在列表中点击目标工序的"删除"按钮
系统弹出二次确认对话框
确认后，系统自动校验该工序是否已被历史生产批次使用
安全防错机制：如果该工序的对应业务数据表中已有生产记录，系统将拦截删除操作， 并提示："该工序已被历史生产批次使用过，无法删除，建议将其停用"。此时建议将工序状态改为"停用" 而非删除，以保护历史数据的完整性。

5.8 停用与启用

在编辑工序对话框中，通过开关切换"启用 / 停用"状态。

  • 停用的工序将不再出现在"现场扫码录入"的操作台中
  • 启用后立即恢复在操作台中的显示

5.9 工序与现场操作台的联动

联动机制："现场扫码录入"页面加载时会实时从工序字典中读取所有启用（isActive: true） 的工序，并按排序号渲染操作卡片。这意味着：
  • 在工序管理中新增一个启用状态的工序 → 操作台自动出现新卡片
  • 在工序管理中停用一个工序 → 操作台对应卡片自动消失
  • 修改排序号 → 操作台中卡片的排列顺序同步变更
此联动机制确保管理员的配置立即可在车间操作端生效，无需发版或重启。

6. 现场扫码录入 v2.0 新增

6.1 功能概述

"现场扫码录入"（Process Hub）是为车间现场操作人员量身打造的高效数据录入工具。 其核心设计理念是：扫码即工作——操作工用扫码枪扫描批次条码后，系统自动展示该批次的 所有启用的工序进度卡片，点击任一卡片即可在右侧抽屉中沉浸式填写数据，无需在多个页面间跳转。

6.2 界面布局

  • 顶部搜索栏 — 扫码枪扫描批次条码或手动输入批次号，回车查询
  • 批次信息区 — 显示扫描到的批次基本信息（批次号、产品型号、规格等）
  • 工序卡片矩阵 — 以网格排列当前批次所有启用工序的进度卡片，颜色标识状态
  • 右侧抽屉弹窗 — 点击工序卡片后弹出，包含该工序的完整录入表单

6.3 操作流程

扫码定位批次 — 使用扫码枪扫描线边批次条码（或手动输入批次号），按回车
查看工序进度 — 系统自动展开该批次的全部工序卡片，各卡片颜色标识状态：
  • 未录入 — 该工序尚无任何数据
  • 草稿 — 已有保存但未正式提交
  • 已提交 — 已完成质检确认
  • 已作废 — 该记录被作废处理
工序录入 — 点击目标工序卡片，右侧弹出抽屉弹窗，填写操作参数
保存或提交 — 填写完数据后点击"保存草稿"或"提交"按钮
关闭抽屉 — 关闭抽屉后操作台保持不刷新，可继续点击下一道工序

6.4 扫码容错机制

严格模式：如果扫描的批次号不存在，系统将直接报错并清空输入框，提示用户重新扫码。 系统不会保留无效的输入，以保证车间操作的严谨性。

6.5 工序卡片动态加载

工序卡片不是写死在代码里的。操作台加载时会从"工序管理"的字典表中读取所有启用状态的工序， 并按排序号排列。如果在工序管理中将某个工序停用，对应卡片会从操作台中消失。详见 第 5.9 节 的联动机制说明。

6.6 与旧版"工序管理"的区别

对比维度旧版工序管理 (v1.0)v2.0 双模块体系
工序定义写死在代码中的路由页面工序管理：可动态增删改的字典
数据录入通过批次详情的链接逐一跳转现场扫码录入：扫码聚合 + 抽屉弹窗
页面跳转每道工序需跳转独立页面全部在同一个操作台内完成，零跳转
权限无细分管理配置与操作录入分离，RBAC 权限控制

7. 大屏看板 v2.0 新增

7.1 功能概述

大屏看板是 YT-MES 的数据可视化中枢，定位为"追溯数据神经中枢"。 它采用工业级深色科技风格，通过 SSE（Server-Sent Events）长连接实时推送生产数据， 解决了传统轮询方案的数据更新滞后和页面闪烁问题。

入口：左侧导航 → "大屏看板"，或访问 /big-screen。

7.2 核心视觉设计

  • 配色方案：暗黑背景 + 蓝色发光线条，营造"数据神经中枢"的科技氛围
  • 屏幕适配：采用 transform: scale() 等比缩放，在 1080P、4K 电视上完美适配
  • 特效组件：引入 DataV-Vue3 组件库（数字翻牌器、滚动表格等）增强视觉冲击力

7.3 面板布局

区域位置内容说明
13 道工序数据链路图C 位（中央）以节点+连线形式可视化展示从配料到分选的完整工序流转路径，实时高亮已完成工序
追溯覆盖率 / 数据完整率左侧面板展示批次追溯覆盖率和电芯数据完整率等核心追溯指标
实时分选结果滚播右侧面板滚动展示最新分选的电芯数据（条码、档位、K值、容量等）
关键 KPI 指标卡顶部数字翻牌器展示总批次、进行中、已完成、电芯总数等关键数据

7.4 数据推送机制

大屏看板后端采用 SSE（Server-Sent Events） 而非传统的 HTTP 轮询。后端每隔 5 秒通过单向长连接 向前端推送最新的生产指标数据。前端基于 Vue 响应式系统实现图表局部更新， 而非整页刷新，从而消除了"白屏闪烁"的问题。

7.5 使用建议

  • 推荐在车间悬挂的 55 寸以上 4K 电视上全屏展示（按 F11 进入浏览器全屏模式）
  • 大屏为只读展示，无需交互操作，数据自动更新
  • 如需关闭，按 Esc 退出全屏后通过左侧导航离开

8. 质量检验

8.1 功能概述

质量检验模块用于记录和跟踪生产过程中的质量检查数据。质检记录关联到具体批次，包含检验结果、缺陷数量和原因描述。

8.2 查看质检记录

从左侧导航"质量检验"进入，或在批次详情页选择"质量检验"选项卡。

  • 列表展示该批次的所有质检记录
  • 表格包含工序类型、检验结果（合格 / 不合格）、缺陷数量、检验员等信息

8.3 创建质检记录

点击"新建检验"按钮
选择工序类型（下拉选择）
填写检验结果、缺陷数量及原因、检验员等信息
点击"确定"提交

8.4 质检与工序的关系

说明：每道工序在提交时也会记录质检数据（如粘度记录等），与独立的质检模块互补。 工序提交时的质检数据针对该工序操作质量，质检模块可记录跨工序的专项检查结果。

10. 电芯追溯

10.1 功能概述

电芯追溯是 YT-MES 的核心功能。通过为每一个电芯分配唯一的条码（Barcode）， 系统记录了该电芯从配料到分选全部 13 道工序的生产数据。通过扫描或输入条码， 可在几秒钟内获取电芯的完整生产履历。

v2.0 新增了分选机自动上传功能，分选机设备可直接将电芯条码及测试数据 通过 API 上传至系统，无需人工导入。详见 附录 D 分选机数据接口。

10.2 电芯条码管理

方式一：手动导入

从左侧导航进入"电芯条码管理"
选择目标批次
在文本框中输入或粘贴电芯条码（每行一个）
点击"导入"按钮
导入成功后可在下方列表中查看该批次的所有条码

方式二：分选机自动上传 v2.0

分选机完成电芯测试后，可通过系统提供的 REST API 自动将电芯条码、容量、电压、内阻、K值、 档位等数据上传至系统。支持单条实时上传和 CSV 表格批量上传两种模式。详见 附录 D。

条码格式：条码为 32 位字符，系统在导入和上传时均会自动进行去重校验，防止重复数据。

10.3 电芯追溯查询

追溯页面布局

电芯追溯页面分为以下区域：

  • 搜索栏 — 支持按条码搜索或按批次号搜索两种模式
  • 批次信息卡 — 显示电芯所属批次的基本信息
  • KPI 指标卡 — 显示电压、内阻、容量、K值、等级等关键参数
  • 工序状态导航 — 13 道工序的完成状态进度条，已完成项高亮显示，点击可查看工序详情
  • 工序详情面板 — 选中某道工序后，展示该工序的详细参数（按设备参数、材料参数、工艺参数、操作信息分组）
  • 电芯列表（批次模式）— 批次模式下展示该批次所有电芯的条码

追溯方法一：按条码追溯

在搜索栏选择"条码搜索"模式
输入或扫描 32 位电芯条码
按回车或点击搜索按钮
系统展示该电芯完整的全生命周期数据

追溯方法二：按批次追溯

在搜索栏切换至"批次搜索"模式
输入批次号
系统展示该批次所有电芯信息及 13 道工序记录

10.4 追溯数据解读

追溯结果中的工序详情面板按以下分类展示数据：

  • 设备参数 — 该工序使用的设备编号、型号等
  • 材料参数 — 该工序使用的材料型号、批次等
  • 工艺参数 — 该工序的工艺设定值与实测值
  • 操作信息 — 操作人员、操作时间、记录状态等
应用场景：当电芯出现质量问题时，通过条码追溯可快速定位问题工序和操作人员， 辅助质量分析和改进。同时，全流程数据记录满足下游客户对电芯生产透明度的要求。

  • 锁定时间为 15 分钟
  • 锁定期间无法登录，15 分钟后自动解锁
  • 请联系管理员处理异常锁定

A. 常见问题

A.1 登录时提示"账号已被锁定"

连续 5 次密码错误导致账号锁定。请等待 15 分钟后自动解锁，或联系系统管理员手动解锁。

A.2 保存草稿后还能修改吗？

可以。草稿状态的工序记录可以反复修改。但一旦点击"提交"，记录将最终确认，不可再修改。提交前请仔细核对数据。

A.3 为什么我提交不了工序记录？

请确认：① 操作工字段已完整填写；② 质检字段也已填写完毕；③ 您有质检权限（角色编码 2 或 4）。只有操作工草稿 + 质检提交两个阶段都完成后才能最终提交。

A.4 创建批次后找不到批次号

批次号由系统自动生成。创建成功后页面会刷新列表，新批次通常排在最前面（按创建时间倒序）。也可以使用搜索功能按产品型号或规格查找。

A.5 导入条码时提示格式错误

请确认每个条码为 32 位字符，每行一个条码，不要包含多余的空格或特殊字符。系统支持批量导入，但不允许重复条码。

A.6 电芯追溯查不到数据

可能的原因：① 输入的条码不完整或有误，请确认 32 位完整条码；② 该电芯尚未导入系统（人工导入或分选机上传）；③ 按批次搜索时批次号输入有误。请仔细核对后重试。

A.7 忘记密码怎么办？

请联系系统管理员重置密码。管理员可以在系统后台为用户设置新密码。

A.8 现场扫码录入扫描批次号后提示不存在 新增

现场扫码录入采用"严格模式"：如果批次号不存在或输入有误，系统会直接报错并清空输入框。请确认批次号完整无误后重新扫码或输入。

A.9 工序管理中为什么看不到"新增"/"编辑"/"删除"按钮？ 新增

这些操作按钮仅对管理员（admin）可见。如果您使用的是 operator1 / quality1 / warehouse1 等非管理员账号，请切换到 admin 账号登录。

A.10 删除工序时提示"已被历史生产批次使用过" 新增

这是系统的安全防错机制。该工序的数据表中已存在生产记录，直接删除会导致历史数据关联断裂。建议将该工序停用而非删除（在编辑对话框中将状态开关关闭即可）。

A.11 大屏看板在大电视上显示不完整 新增

请确保：① 浏览器已按 F11 进入全屏模式；② 电视机分辨率设置为 1920×1080 或 3840×2160；③ 系统自动采用等比缩放适配，不同分辨率下排版保持一致。

A.12 系统响应慢怎么办？

请尝试：① 刷新浏览器页面；② 检查网络连接；③ 联系系统管理员确认服务器运行状态。大批量数据操作（如导入数万条码）可能需要一定处理时间。

D. 分选机数据接口 v2.0 新增

D.1 概述

系统为分选机等外部硬件设备提供了两个独立的 REST API 接口，用于将电芯测试数据 （条码、批次、容量、电压、内阻、K值、档位、分选时间等）上传到 YT-MES 的 cell_barcode 表中。

接口采用无状态设计，免登录认证（@Public()），方便硬件设备直接调用。 两个接口分别服务于单条实时上传和批量表格导入两种使用场景。

D.2 接口端点

POST /api/cells/sorter-upload
单条实时上传 — 分选机每测完一个电芯，实时上传一条数据
POST /api/cells/sorter-upload/bulk
批量表格推送 — 分选机将本地 CSV/XLS 表格中的所有电芯数据一次性上传

D.3 单条上传 (POST /api/cells/sorter-upload)

请求格式

POST /api/cells/sorter-upload
Content-Type: application/json

{
  "barcode": "E2405A0000000000000000000000001",
  "batchNo": "WT26A1XZ8",
  "capacity": 20500,
  "voltage": 3.65,
  "resistance": 1.25,
  "kValue": 0.08,
  "grade": "A",
  "sortingTime": "2026-05-10 14:30:00"
}

字段说明

字段类型必填说明
barcodestring是电芯条码（32 位唯一标识）
batchNostring是所属批次号
capacitynumber是电芯容量（mAh）
voltagenumber是开路电压（V）
resistancenumber是交流内阻（mΩ）
kValuenumber否K 值（自放电率，mV/h）
gradestring是分选档位（A / B / C）
sortingTimestring是分选时间（格式：YYYY-MM-DD HH:mm:ss）

成功响应

{
  "success": true,
  "data": { "id": 12345, "barcode": "E2405A0000000000000000000000001" },
  "message": "上传成功"
}

失败响应（条码重复）

{
  "success": false,
  "data": null,
  "message": "条码 E2405A0000000000000000000000001 已存在，请勿重复上传"
}

D.4 批量上传 (POST /api/cells/sorter-upload/bulk)

请求格式

POST /api/cells/sorter-upload/bulk
Content-Type: application/json

{
  "records": [
    {
      "barcode": "E2405A0000000000000000000000001",
      "batchNo": "WT26A1XZ8",
      "capacity": 20500,
      "voltage": 3.65,
      "resistance": 1.25,
      "kValue": 0.08,
      "grade": "A",
      "sortingTime": "2026-05-10 14:30:00"
    },
    {
      "barcode": "E2405A0000000000000000000000002",
      "batchNo": "WT26A1XZ8",
      "capacity": 20300,
      "voltage": 3.64,
      "resistance": 1.30,
      "kValue": 0.06,
      "grade": "B",
      "sortingTime": "2026-05-10 14:30:05"
    }
  ]
}

去重校验

批量上传会自动执行两层去重校验：

  1. 请求体内去重 — 检查传入的 JSON 数组中是否存在重复条码
  2. 数据库去重 — 检查每条条码是否已存在于 cell_barcode 表中

如发现重复，系统会返回具体哪条条码发生了冲突。

成功响应

{
  "success": true,
  "data": { "count": 150 },
  "message": "批量上传完成，共导入 150 条记录"
}

D.5 调用示例

cURL 示例

# 单条上传
curl -X POST http://localhost:3001/api/cells/sorter-upload \
  -H "Content-Type: application/json" \
  -d '{
    "barcode": "E2405A0000000000000000000000001",
    "batchNo": "WT26A1XZ8",
    "capacity": 20500,
    "voltage": 3.65,
    "resistance": 1.25,
    "kValue": 0.08,
    "grade": "A",
    "sortingTime": "2026-05-10 14:30:00"
  }'

Python 示例

import requests

url = "http://localhost:3001/api/cells/sorter-upload"
data = {
    "barcode": "E2405A0000000000000000000000001",
    "batchNo": "WT26A1XZ8",
    "capacity": 20500,
    "voltage": 3.65,
    "resistance": 1.25,
    "kValue": 0.08,
    "grade": "A",
    "sortingTime": "2026-05-10 14:30:00"
}
response = requests.post(url, json=data)
print(response.json())

D.6 注意事项

重要：
  • 接口无需 Token 认证，部署时请在网络层面（防火墙/网关）限制访问来源 IP
  • 条码字段必须为 32 位字符，批次号需先在系统中创建
  • 批量上传接口单次建议不超过 10000 条记录，大量数据请分批次调用
  • 接口返回的错误信息会明确指出具体是哪条数据出了问题，请仔细阅读响应中的 message 字段
