# OCV1/OCV2 工序参数页面对齐设计

## 目标

将 OCV1 和 OCV2 工序页面调整为批次级工序参数编辑页，两个页面的输入字段严格与参数配置一致：

- 设备编号 `equipmentCode`
- OCV 电压范围 `ocvVoltageMin` / `ocvVoltageMax`
- 内阻范围 `irMin` / `irMax`
- 容量范围 `capacityMin` / `capacityMax`
- 操作员 `operatorName`

两个页面都不再展示电芯码、实测 OCV 电压、实测内阻、测试时间或 K 值。这些属于逐电芯测试上传数据，不属于本次工序参数编辑范围。

## 方案

前端将 `Ocv1Page` 和 `Ocv2Page` 从当前的逐电芯 OCV 上传表单改为参数编辑表单，沿用普通工序参数页的范围输入、必填校验、当前登录用户默认操作员和保存后关闭抽屉的交互。两者共用参数表单组件，仅通过工序编码区分记录。

后端不复用现有 `ocv1_record`/`ocv2_record` 历史上传表。两张表当前由 OCV 上传接口按电芯写入，直接复用会把批次参数和历史测量记录混在一起。新增独立的批次工序参数存储，按 `batchNo + processCode` 唯一定位，保存上述五类参数，并提供查询和保存接口。

现有 OCV1/OCV2 逐电芯上传接口保持不变，后续如需现场测试上传，应从独立入口进入，不与参数编辑页混用。

## 数据流

1. 打开批次 OCV1 或 OCV2 工序页。
2. 前端按工序编码读取该批次的参数记录；没有记录时显示空表，并将当前登录用户作为操作员默认值。
3. 用户填写设备编号、三个范围和操作员。
4. 保存前校验所有必填值以及每个范围的最小值不大于最大值。
5. 前端调用批次工序参数保存接口。
6. 后端按批次和工序执行新增或更新，返回保存后的参数记录。
7. 保存成功后关闭抽屉并刷新批次工序状态/参数摘要。

## 验收标准

- OCV1 和 OCV2 参数页面都只出现图示五类参数，不出现电芯码、实测电压、实测内阻、测试时间或 K 值。
- 字段名称、单位、范围输入结构和必填状态与参数配置一致。
- 页面加载能回显已保存的五类参数。
- 范围反向时不能保存，并给出明确提示。
- 保存后刷新页面，参数仍保持；重复保存更新同一批次 OCV1 参数，不产生重复记录。
- OCV1 和 OCV2 的参数记录相互隔离；现有 OCV1/OCV2 逐电芯上传接口及追溯数据不受影响。

## 测试

- 前端组件测试确认 OCV1 和 OCV2 都只渲染五类参数字段。
- 前端组件/API 测试覆盖读取、保存和范围校验。
- 后端服务测试覆盖按批次工序新增、更新和查询。
- 后端回归测试确认现有 OCV1/OCV2 上传仍按原 DTO 工作。
