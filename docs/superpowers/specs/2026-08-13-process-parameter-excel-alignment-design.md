# 工序控制参数按 Excel 基线更新设计

## 目标

以 `doc/云通MES系统  工序控制参数列表260813.xlsx` 为普通工序参数的唯一基线，更新云通 MES 的工序字典、动态参数配置和工序顺序；新增“入壳”“一体机”“激光焊接”三个独立工序，并保持历史批次数据可追溯。

## 已确认的业务规则

1. Excel 中“入壳”“一体机”“激光焊接”作为三个独立工序加入系统。
2. 三个新工序排在“装配”之后，顺序为：
   `装配 → 入壳 → 一体机 → 激光焊接 → 烘烤`。
3. Excel 中“分选出货（OCV）”归入现有“分选”工序，不新增独立工序。
4. “封口”下的化成模板、化成温度、分容模板、分容温度、容量分级标准全部保留在“封口”，不拆分到“化成”或“分容”。
5. Excel 是普通工序参数的唯一基准；系统中 Excel 未定义的普通工序参数从当前可录入字段配置中删除。
6. Excel 中的“设备信息”是参数分组标题，不生成录入字段。
7. “操作员”作为普通工序通用录入字段保留。
8. OCV1、OCV2 的专用业务逻辑、接口和记录结构保留，不改造成普通工序参数，也不删除。
9. 删除范围仅限可录入字段定义；历史批次已保存的参数 JSON 和记录不删除。

## Excel 参数映射

Excel 的每个参数行转换为工序字典的动态 `fieldDefinitions`。每项包含稳定的英文 `key`、中文 `label`、Excel 中的单位 `unit`、录入 `type`、所属 `group` 和必填规则。参数类型按 Excel 的“格式”列映射：

- `文本` → `text`
- `数字` → `number`
- 带单位的数值格式（如 `mm`、`℃`、`m/min`、`kg/N`）→ `number`
- 未填写格式的文本类检查项（如外观、焊接效果）→ `text`
- `操作员` → `text`，使用现有登录用户默认值并禁止编辑

同一工序中的“设备信息”等标题行用于建立分组上下文，不进入字段列表。Excel 的“分选出货（OCV）”分组内容追加到“分选”的字段定义中。

对于 Excel 中名称重复的参数（例如“内阻电压范围”），必须依据分组和单位生成不同的稳定 key，不能在动态表单中产生重复 key；映射表中明确记录其中文名称、单位和来源分组。

## 工序字典与排序

普通工序目标顺序为：

1. 配料
2. 涂布
3. 辊压
4. 分切
5. 制片
6. 卷绕
7. 装配
8. 入壳
9. 一体机
10. 激光焊接
11. 烘烤
12. 注液
13. 封口
14. 分选

已有系统编码继续沿用；新增工序使用稳定编码并在迁移、seed、前端组件映射和测试中保持一致。OCV1、OCV2 是否显示在专用测试入口中沿用现有系统规则，不纳入上述普通参数基线排序。

## 数据更新方案

采用“迁移已有数据 + 更新 seed 默认值”的双路径：

- 新环境通过 seed 获得正确的工序字典和字段定义。
- 已有环境通过幂等数据库迁移更新工序名称、排序、启用状态和 `fieldDefinitions`。
- 迁移只更新目标工序的定义，不删除历史工序记录或历史批次参数数据。
- 迁移应能重复执行而不重复插入新工序，并处理已有同编码记录。
- 删除旧字段前保存变更来源和映射结果，便于审计和回滚设计评估。

## 前端与后端影响

- 工序字典接口继续作为动态表单配置来源。
- 工序入口根据新增工序编码加载对应的录入组件；普通新工序可复用动态 `ProcessFormPage`。
- 工序状态、批次详情和工序中心的顺序来自工序字典，不额外维护冲突的硬编码顺序；如存在硬编码列表，需同步更新。
- 普通参数仍保存为现有工序记录中的参数对象，不能因为删除字段定义而清理已保存对象中的旧属性。
- OCV 专用 API、实体、参数抽屉和测试保持兼容。

## 校验与异常处理

更新前生成 Excel → 系统现状的差异清单，至少报告：新增字段、删除字段、名称变化、单位变化、重复 key、未映射工序和未知格式。任何无法确定的工序或字段映射不得静默丢弃，应在迁移前以明确映射处理。

动态字段配置保存时继续校验 key 唯一性。数字字段使用数字控件；文本/外观类字段使用文本控件；操作员字段沿用登录用户默认值。对于无单位的“焊针外径”等字段，保留无单位数字字段，不擅自补充单位。

## 验证标准

1. 参数差异检查确认普通工序字段与 Excel 一致，Excel 未定义字段不再出现在当前录入配置中。
2. 工序字典包含新增的三个工序，顺序符合确认结果。
3. 分选包含 Excel 的 OCV 参数；封口包含化成、分容相关参数。
4. 动态表单能加载、填写、保存和提交新增工序及现有工序。
5. 历史批次参数记录仍可读取，旧字段值未被删除。
6. 数据库迁移可重复执行且不产生重复工序。
7. OCV1/OCV2 现有单元测试和接口行为不受影响。
8. 通过服务端测试、前端测试、类型检查和生产构建。

## 不在本次范围内

- 不删除 OCV1、OCV2 专用业务模块。
- 不将 Excel 中的所有参数改造成独立数据库列。
- 不清理历史批次已保存参数。
- 不拆分封口下的化成、分容字段。
- 不新增独立“分选出货（OCV）”工序。
